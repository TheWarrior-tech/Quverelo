# Quvrelo design system

Status: v3 shell + critique-2 shell fixes + critique-3 units, overflow, scrollbars, adjustment cards + critique-4 active layer, Text inspector and high-contrast selection vocabulary (2026-10-15; v1 2026-10-14). Source of truth for every screen. Tokens live in `src/renderer/styles.css` (`:root`, `[data-theme]`); icons in `src/renderer/ui/Icons.tsx`. If a screen needs a value that is not here, add it here first.

## 1. Intent

Quvrelo is a tool for making things, so the interface should disappear: calm graphite surfaces, one accent, hairlines instead of boxes, dense but never cramped, numbers that don't jiggle. A first-time student should find the tool in one glance; a pro should never wait on a transition.

Feel references (studied for structure and restraint, nothing copied): Linear (charcoal ramp, 13px UI, translucent hairlines, 4/6/8 radii), Raycast (single accent, tiny type, keycaps), Glyphs (tool-first, one accent), Figma / Affinity V3 (panel density, 24–28px rows), Arc (quiet chrome). Pattern notes from Mobbin (Framer, FLORA, Descript, Frame.io): two radii only, selection is a colour swap not a pill of colour, accent in four roles only, segmented controls as contained pills with a contrasting active tile, dialogs on a dimmed backdrop with a hairline above the footer, a single thin accent playhead. Notes: `docs/design/refs/NOTES.md`.

## 2. Anti-slop rules (reviewable, each is a checklist item)

1. No gradients on chrome, buttons, cards or logos. (Gradients only inside user artwork and the colour picker.)
2. No glass / blur blobs, no coloured glows, no drop shadows on resting controls.
3. No emoji, no unicode glyphs as icons (`✕ ▲ ▼ ＋`). Every icon comes from `Icons.tsx`.
4. Exactly one accent colour (verdigris). It appears only on: the active tool, the one primary button per view, focus rings and selection outlines, slider/checkbox "on" state, text links. Studios are not colour-coded.
5. Two radii: `4px` controls, `8px` containers (dialogs, cards, popovers). `999px` only for knobs and count pills. Nothing in between.
6. Elevation: resting surfaces are flat and separated by one-stop tone shifts and 1px hairlines. Only popovers/dialogs/toasts carry a shadow (plus the scroll-edge shade, §6, shown only while a panel is scrolled).
7. Left-aligned, grid-aligned layouts. No centred hero blocks inside the app.
8. Every number is tabular (`font-variant-numeric: tabular-nums`).
9. Motion ≤ 150 ms, ease-out, opacity/transform only, removed under `prefers-reduced-motion` and the in-app "reduce motion" setting.
10. Nothing is decorated unless it carries meaning.

## 4. Type

Typeface: **Inter** (SIL OFL, bundled via `@fontsource/inter`, weights 400/500/600). Monospace only for keycaps: system `ui-monospace`. Document typefaces (Merriweather, Roboto Slab, Caveat, Atkinson, OpenDyslexic) are content, never chrome. Dyslexia-friendly chrome option swaps `--font-ui`.

Features: `"cv11" "ss03"` off; `"tnum" "calt"` on for numerals; tracking −0.005em at 12–13px.

| Role | Size / line | Weight | Use |
|---|---|---|---|
| `--t-micro` | 11 / 16 | 500, +0.04em, uppercase | panel section labels |
| `--t-ui` | 12 / 16 | 400 / 500 | all panel and toolbar text, inputs |
| `--t-body` | 13 / 20 | 400 | dialog body, menus, descriptions |
| `--t-title` | 14 / 20 | 600 | dialog titles, card titles |
| `--t-h2` | 18 / 24 | 600, −0.01em | welcome section headings |
| `--t-display` | 24 / 28 | 600, −0.02em | welcome title only |

Weights: 400 body, 500 labels/controls in active state, 600 titles. Never 700+.

**Case.** Sentence case for every string Quvrelo draws: buttons, dialog titles, tabs, headings, labels, tooltips, tool names, toasts (“Document setup…”, “Check for updates”, “Don't save”, “Rectangle marquee”). Two exceptions: native menu items keep platform Title Case (`shared/menu.ts`), and so do the command-palette rows that mirror them and any text that quotes a menu item as a path (“File › Place Image”); proper nouns (Quvrelo, font and platform names, keys) keep their capitals. Micro-labels are uppercase by CSS, never typed in capitals. Enforced by `tests/unit/sentenceCase.test.ts` over `ui/` and the UI-facing `state/` modules.

## 5. Space, size, grid

4px base; allowed steps 4 · 8 · 12 · 16 · 24 · 32 · 48. Control heights: `24` (compact: panel inputs, segmented, small buttons), `28` (default buttons, top bar), `32` (dialog actions). Tool rail buttons `32×32` on a `44px` rail. Panel row height `28`, layer row `28`. Top bar `44` (`--h-top`), context bar `36`, status bar `24`. Shell columns (v3): tool rail `44` (`--w-tools`) · left rail `248` (`--w-rail`) · canvas · inspector `288` (`--w-inspector`). The rails run full height between top bar and status bar; the context bar sits over the canvas column only. All hairlines are 1 device-independent px drawn as `box-shadow`/`border` so they stay crisp at 150 %/200 %.

**Units.** Every length the user reads or types is in the document's own unit (`settings.unit`: mm for a Print preset, in for US paper, px for screen, social and photos), never a global preference. One formatter and one parser in `core/units.ts` (`formatLength` · `formatSize` · `lengthIn` · `parseLength`, precision from `UNIT_DIGITS`: px/pt/mm 1 decimal, cm 2, in 3, trailing zeros trimmed) feed the inspector, context bar, status bar, rulers, Document setup and Export, so the same length never reads two ways. Stroke widths and brush sizes stay in px/pt.

## 6. Radius, elevation, motion

- Radius: `--r-1: 4px` (buttons, inputs, rows, tiles) · `--r-2: 8px` (dialogs, popovers, cards, thumbnails) · `--r-full: 999px` (knobs, count pills). One derived value, `--r-tile: calc(var(--r-1) - 1px)`, for tiles inset inside a 4px track (segmented controls) and checkboxes, and `--r-hairline: 1px` for 2px tracks, ticks and insertion bars (slider track, checklist progress, layer drop line, orientation glyph, spread page corners). No literal radii anywhere else (`tests/unit/shellLint.test.ts` rejects a px `border-radius` outside the tokens).
- Elevation: `--e-0` none · scroll edges (the one exception on resting chrome): a hairline plus a short soft shade appears at the top/bottom of a scrolling panel only while content is hidden past that edge · `--e-1` popover `0 0 0 1px line, 0 4px 16px rgba(0,0,0,.28)` · `--e-2` dialog `0 0 0 1px line, 0 16px 48px rgba(0,0,0,.4)`.
- Motion: `--dur: 120ms`, `--ease: cubic-bezier(.2,.7,.3,1)`. Allowed: background/colour/opacity fades, 4px toast slide, dialog 4px rise. No bouncing, no scaling on hover.

## 7. Iconography

Custom set drawn for Quvrelo (`src/renderer/ui/Icons.tsx`), no third-party glyphs.
- Grid `20×20`, live area `16×16` (2px padding), pixel-aligned to 0.5.
- Stroke `1.5`, `round` caps and joins, never filled except `mask`, `adjust`, tiny anchor dots. Corner radius `1.5` on rects, `1` on small squares.
- Displayed at `20px` in the tool rail (1:1 on the grid) and `16px` inline (stroke bumps to `1.75` so it still reads as 1.4px).
- Colour is `currentColor`; active tool rail icon uses accent-ink on accent fill.
- Studios have glyphs (photo = aperture, vector = node curve, layout = columns). No coloured studio badges.

App icon / logo: graphite tile, off-white ring, one accent bar forming the Q tail. Flat, no gradient, no shadow. Source `build/icon.svg`; `build/icon-small.svg` is the 16–32px variant (near full-bleed tile, no inner hairline, heavier ring and tail). Re-render every raster with `scripts/render-icons.cjs` (each size rasterised from vector).

Icon buttons: use `tip(label, commandId | key)` from `ui/tooltip.ts` — `aria-label` is the name, `data-tip` is the tooltip text and `data-keys` the shortcut read from the app menu (drawn as keycaps by `ui/Tooltip.tsx`), `aria-keyshortcuts` is set. Never use the native `title` attribute; any left over is taken over by the tooltip host on hover.

## 8. Components

**Shell v3 layout.** Four columns under the top bar: tool rail · left rail (document structure) · canvas (context bar on top) · inspector. Tab (outside a field) hides both rails. Grid and geometry live in `ui/shell.css`; nothing in the shell is positioned with inline styles except runtime geometry (popover/toolbar coordinates, virtualised rows, font-face previews), which `tests/unit/shellLint.test.ts` enforces.

**Top bar (44), three semantic zones** (Mobbin cross-app pattern 4). The outer columns are equal width and the centre column holds only the studio switch, so the switch sits on the window's centre line (±1px, e2e-checked).
1. *Identity* (left): app mark · document name (500, truncates at 280; click to rename in place, Enter commits, Esc cancels) · save state as quiet 11px text with a 6px dot: `Saved` (hollow `text-3` dot), `Edited` (solid `text-2` dot, `text-2` label; status is never accent, §2 rule 4), `Not saved` (never saved) · a 16px hairline · Undo · Redo · Place image (28×28 icon buttons).
2. *Studio* (centre): the studio switch, nothing else.
3. *Outbound* (right): **Search commands** field-button (28 high, 200 wide, `--c-raised`, hairline; 16px search icon, "Search commands" 12 `text-3`, `Ctrl` `K` keycaps; opens the command palette; below 1280px it collapses to a 28×28 icon button), then Open · Save · Keyboard shortcuts · Preferences icon buttons, then **Export** as the only filled primary button in the bar (icon + label, 28 high). Align and boolean actions moved to the inspector and the selection toolbar.

**Studio switch.** Segmented control: 28 high, 4px inner padding, `--c-raised` track with hairline, active segment `--c-press` fill + text primary, icon in accent. Neither colour-coded nor underlined. Keyboard: arrow keys move, Enter selects.

**Tool rail (44 wide).** `--c-app`, hairline right. 32×32 buttons, 2px gap, groups divided by an 8px gap plus a 16px hairline (no heavy dividers). Active = solid accent with accent-ink icon. Tooltips show name + shortcut as keycaps. **Flyouts:** related tools share one button (layout and groups in `state/toolGroups.ts`): it shows the active or last-used member and carries a 4px corner triangle (bottom-right, 3px inset, `currentColor` at 80 %). Click uses the shown tool; right-click, a 350ms long-press, →, Alt+↓, Shift+F10 or the context-menu key open the flyout (press-drag-release on an item picks it). Flyout = `role="menu"` beside the button (4px gap, first row level with the button): `--c-popover`, `--r-2`, `--e-1`, 4px padding, 28px `menuitemradio` rows with 4px radius (check · 16px icon · name · keycap in `text-3`), the shown tool checked with `--c-press` fill. High contrast uses the §9 selection vocabulary: checked = solid `#ffd400` tile with black text, icon and keycap, focused = the HC ring (3px yellow outline, 2px offset) on a black row, hover = 1px white inset; rows are 6px apart so a ring never touches a checked tile. ↑/↓/Home/End move, Enter/Space or a tool's letter picks, Esc/←/Tab close and return focus. Shift + any member's key cycles the group; a member without its own key advertises `Shift+<group key>` in its tooltip. Tool keys are per studio (`TOOL_KEYS` in `state/toolGroups.ts`). **Photo** has a Shapes flyout after Text (Rectangle · Ellipse · Polygon · Star, key `U`, Shift+U cycles, since M is the marquee and E the eraser there); a shape drawn in Photo is a vector layer inserted directly above the active layer. 120ms fade + 4px slide, none under reduced motion. Colour chips at the bottom: two overlapping 20px squares, 1px line-strong border, swap icon.

**Context bar (36).** Tool name at 500, then controls in groups separated by a 16px hairline. Sliders show label, 96px track, tabular value. Modes (New/Add/Subtract/Intersect) are a segmented control. Hint text is `text-3`, never competes with controls. **Priority+ overflow** (`controls/CtxOverflow.tsx`): the bar never scrolls and never cuts a word. When its groups don't fit the canvas column, the hint is dropped first (a hint is dropped rather than shown cut short), then groups collapse, lowest `<Pri n>` first (ties right to left), into a trailing ghost **More ▾** button whose popover holds them in a column. Page navigation and crop Cancel/Apply never collapse. Layout Move: Pages (always) · Margins (4; T · B · L · R, the same order as Document setup) · Document setup (3) · Facing pages (2.5) · Columns (2) · Bleed (1). E2e-checked for every studio and tool at 1280 and 1440 (`scrollWidth ≤ clientWidth`).

**Left rail (248).** Tabs **Layers · Pages · Assets** (Figma/Framer pattern), 36px header with a hairline below. Tabs are text buttons (active = primary text on `--c-press`, 4px radius, no underline; arrow keys/Home/End move and select). Default tab: Layers in Photo and Vector, Pages in Layout; the choice is remembered per studio. Assets holds document swatches + recent colours, then Shapes & symbols, then placed Images (with a teaching empty state).

**Inspector (288).** Tabs **Design · Adjust (Photo only) · History**, remembered per studio. The Design tab is grouped by concern, in this order:
1. Header 32: object name (13/600, the same display name as the layer row) and, when it differs from the name, its kind in `text-3` 11/500.
2. Align bar 36: six align buttons, hairline, distribute H/V (enabled at 3+), Boolean menu (Vector, 2+).
3. **Appearance**: Fill row · Stroke row (+ width · dash · cap · join when on) · Opacity slider · Blend. Text and text frames show *Colour* in place of Fill. This is the one home for Opacity and Blend in every studio, Photo included (pixel layers show Opacity · Blend here).
4. **Text** (text and text frames only; CRITIQUE-4 N11): the full, persistent home for type. Font picker (full width, set in its own face) · Style (weight + italic, "Bold italic") + Size in pt (grid2) · Leading (×, line-height multiple) + Tracking (thousandths of an em), each with a 16px glyph scrub label and a tooltip (grid2) · alignment as an icon segmented control (left · centre · right · justify) · a ghost **More type options** disclosure with Capitals (Normal · Small caps · All small caps) and the Kerning and Underline checkboxes (the OpenType basics the canvas, SVG and PDF writers honour; small caps go to the PDF image fallback). Vertical alignment and paragraph spacing are not in the text model yet.
5. **Transform** (the document unit in the header): one 4-up row X · Y · W · H (no unit suffix, so five digits fit), then R · S · flip H · flip V.
6. The object's own section last, titled for what it edits so it never repeats the header: *Corners* (rectangle radius), *Sides* (polygon), *Points* (star points/inner), *Text frame* (columns · gap · inset, frame fill, then *Link frames* and *Unlink* as two `btn sm ghost` buttons; Unlink is disabled while the frame has no link), *Image fit* (picture frame fit/zoom/offset/replace), *Pixels*; then Mask.
Nothing selected: Document (title, size in the document unit with the output pixels as an 11px `text-3` second line, "2480 × 3508 px at 300 dpi", pages, background chip) and *New objects* (default fill/stroke rows). Rows use a 56px label column; sections are flat with a micro-label disclosure (remembered per section), hairline between, and a section you expand scrolls itself into view.

**Colour control (one everywhere).** `ColorChipButton` is the only colour trigger in the shell: a 20px chip (optionally with a chevron in the context bar) that opens `ColorPopoverBody` in a popover. There is one popover body: title, then the paint-type tabs **None · Solid · Linear · Radial** as the first row (always all four, in that order), then the picker (Solid) or the gradient editor. A target that can't take a type (brush and flood fill: no None, no gradients; text: no None; document background: no gradients) shows that tab disabled with a tooltip, never hidden, so the body is identical in the inspector, context bar, selection toolbar, tool rail and Document section. No "None" checkbox anywhere. The chip takes a `Paint` and returns a `Paint`; defaults for new objects are read and written through `state/uiPaint.ts`, so a default fill or stroke can be a gradient too. The inspector's `PaintRow` is chip · hex field · add/remove; its chip opens to the *left* of the inspector so it never covers the panel. **Placement rule (every colour popover):** it never covers the inspector or the selected object it edits, so the change is visible live. An inspector chip places against the inspector's left edge (`right = inspectorLeft − 8`); a context-bar, selection-toolbar or tool-rail chip takes the first side that keeps the selection's screen bounds, the inspector and its own anchor clear (below/above the anchor, then left/right of the selection), and falls back to below only when nothing fits (`ui/controls/placement.ts`, unit- and e2e-tested). No native `<input type="color">` anywhere in the shell. Chrome is off limits too: a colour popover never rides over the top bar or the context bar (both are keep-clear rects; it opens below the context bar or beside the selection and slides horizontally; CRITIQUE-4 P2-19). A transparent document background shows the transparency checker in its chip (inspector and Document setup), never the None diagonal or a stale white swatch.

**Layers.** No header controls: opacity and blend are edited only in Design › Appearance (all studios). Row 28, full bleed: 16px indent per group level, chevron twisty, 24×20 thumbnail (4px radius, 1px `--c-line-strong` inner frame; vector thumbnails tint the type glyph with the fill, falling back to `text-3` when the fill is under 1.5:1 against the tile, so a white "Paper" layer never vanishes on the light theme), name (12; text layers that were never renamed show their text, whitespace collapsed, and only the CSS ellipsis truncates it (never a word cut plus an ellipsis), with the full name in the row tooltip; "Text Frame" only when empty; F2 renames and the name then sticks), status icons (mask, live adjustments) in `text-3`, then lock/eye toggles that appear on hover, keyboard focus or selection, and stay visible while they carry state (hidden, locked); at rest a stateless toggle takes no width, so the name uses the whole row before the ellipsis. Rows are inset 4px with a 4px radius. Hover = `--c-hover` fill only; selected = accent-wash fill + 2px inset accent bar + name at 500 (hover on a selected row keeps the wash, never the grey hover). Hovering a row draws the hover outline on the canvas. High contrast follows the §9 selection vocabulary: selected = solid yellow fill with black name, icons and toggles; keyboard focus = 3px yellow ring 2px outside a black row; selected + focused = both; hover = 1px white inset; rows sit 6px apart; no washes. **Empty state:** a teaching block, never a bare line: 32px glyph tile, “No layers yet” (13/600), one line on what lives here, then ghost actions *Place image* · *Draw a shape* (Photo: *Paint*) · *Add text*, and “Or drop an image file onto the canvas.” in `text-3`. When the canvas shows its own empty card (an empty page), the card owns the actions and the Layers empty state shrinks to glyph, title and one line, so two empty states never offer the same buttons. Drag: the dragged row dims, insertion = 2px accent line with a 6px ring at its start, above or below the hovered row. Keyboard: ↑/↓ move focus, ←/→ collapse/expand, Enter selects, F2 renames, Alt+↑/↓ reorders, Alt+H toggles visibility. Footer actions are 24×24 icon buttons: **+** (Add layer) opens a menu above it: Pixel layer · Group selection (2+) · Place image… · in Photo an *Adjustment* heading with the adjustment list (disabled, "Select a pixel layer first", until a pixel layer is selected); then Group · Mask · Duplicate · Forward · Backward · Delete.

**Segmented control (shared).** `ui/controls/Segmented.tsx` is the one implementation (radio group, roving focus, arrows move and select; optional icon-only segments with an accessible name; disabled segments skipped; `disabled` locks the whole group). `sm` = 24 track / 20 tiles (panels, context bar, colour picker), `md` = 28 / 24 (dialogs, via the `dialogs/controls.tsx` adapter, which only sets the size). Used for every one-of-few choice: paint type, colour model, selection mode, frame fit, dialog options (orientation, background, update channel, resize mode, export pages/background). There is no other segmented style (`.seg` and `.choice-row` are gone, the Curves channel switch included; `tests/unit/shellLint.test.ts` guards it). Tokens: track `--c-seg-track` with a `--c-line` hairline; active tile `--c-seg-on` + 1px `--c-seg-ring`, label `--c-seg-on-text` at 500.

| | Dark | Light | High contrast |
|---|---|---|---|
| track | `#1e1f21` | black 6 % | `#000` + 1px white |
| active tile | `#222326` + 1px white 34 % ring | `#fff` + 1px black 43 % ring | `#ffd400` fill, black label |
| disabled | 40 % opacity | 40 % opacity | no opacity: label `text-3`; active = black tile, 1px dashed white outline |

Disabled never means translucent accent. The contrast audit checks that the active tile differs from the track (fill ≥ 1.4:1 or ring ≥ 3:1) on panels and in dialogs, in all three themes.

**Text controls: one quick home.** Type has exactly two homes: the full set in Inspector › Text, and one quick set outside it, which is the **context bar** (font · size · B · I · U · alignment; leading, tracking and OpenType live only in the inspector). The floating selection toolbar carries no text controls. The context bar is the quick home, not the floating toolbar, because: it is visible while text is being typed (the toolbar hides during text editing, which is exactly when a student reaches for size or bold); it sets the defaults for the Text and Text frame tools before any text exists; it cannot be switched off (Preferences › Canvas turns the floating toolbar off); it never covers the text being edited; and it sits in the same place every time, where students already look for tool options (Affinity, Photoshop). E2e-checked: a selected text frame shows exactly one font trigger outside the inspector.

**Context-bar details.** Selection tools carry *Select subject* then labelled ghost buttons *All · Deselect · Invert* (icon + word, tooltips with shortcuts; the group collapses into More before anything is cut). The Move bar offers Group only for 2+ objects and Ungroup only for a group, never a disabled Ungroup. Shape tools disable the stroke width W while the stroke is None. Crop starts at ratio **Original** (the photo's own proportions). There is one page navigator on screen: the context bar's Pages group in Layout Move with nothing selected, else the canvas page pill.

**Context-bar hint (`CtxHint`).** One quiet line in `text-3`, ≤ 60 characters, pattern “Drag to … · Shift …”, truncates with an ellipsis (full text in the tooltip) and hides below 1280px. Never a coloured span.

**Menus (`MenuButton`).** Ghost trigger (icon and/or label + 12px chevron), opens an 8px-radius popover of 28px items (16px icon, label 13, keycaps right in `text-3`); arrows/Home/End move, Enter runs, Esc closes and returns focus.

**Popovers.** Portal to body, placement below/above/right/left with flip-on-overflow (the cross axis slides inside the window), optional rects to keep clear (`avoid`), close on Esc or outside press and return focus to the anchor. Focus moves to the first control once, after placement (`[data-autofocus]`, else the roving tab stop, else the first input/button) and never again on re-render, so committing a value never steals focus.

**Font picker.** Trigger shows the family set in its own face (168 wide in the context bar, 136 borderless in the selection toolbar). ## 9. Accessibility (must not regress)

Focus ring 2px `--c-focus` + 1px offset on every interactive element; high-contrast uses 3px.

**High-contrast selection vocabulary (one rule for every list).** Written once at the end of `styles.css`; no other CSS may style a selected row in high contrast (`tests/unit/shellLint.test.ts`), and `tests/e2e/hc-selection.spec.ts` checks the computed styles.
- *Selected / current / checked / on* (Layers rows, History current step, Preferences / Shortcuts / Export / New-document nav, preset and template tiles, theme tiles, Pages thumbnails, the tool flyout, menus, the command-palette and font-list cursor rows, `.btn.selected`, small icon toggles such as Bold/Italic, Snap; segmented controls, panel tabs and the studio switch already use it): solid `#ffd400` fill, black text, icons, counts and keycap frames, no outline, no wash. Colour swatches, whose fill is their content, draw selected as a 2px yellow edge *inside* the swatch.
- *Keyboard focus*: 3px `#ffd400` outline, 2px offset, on a black row.
- *Selected + focused*: the fill plus the ring; the 2px offset is the black gap between them.
- *Hover*: 1px white inset on a black row; a selected row keeps its fill.
- Rows that take focus sit 6px apart and 6px inside their scroller (Layers, dialog side lists, menus, History, the flyout), so a ring is never clipped and never touches a neighbouring fill.

**High-contrast disabled and dimmed states.** Never translucent (opacity turns yellow into olive and white into a grey that reads as another colour): ink is `--c-disabled` (`#8f8f8f`, still 6.6:1 on black); a bordered control's border turns 1px dashed white; a disabled accent control (primary button, checked box, slider fill, the active segment) is black with a dashed white edge, never yellow. Dimmed but enabled states (a search group with no match, redo-able History steps, a hidden adjustment, paint or layer) use the same ink. Keycaps are one 1px white frame on black; every HC hairline, scroll edges included, is 1px white. All icon buttons have `aria-label`; tooltip text equals label. Target size ≥ 24×24 (WCAG 2.2 AA 2.5.8). Contrast table above. No information by colour alone (active tool also has fill + `aria-pressed`). Reduced motion honoured. Forced-colours supported via high-contrast theme.
