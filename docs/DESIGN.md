# Quvrelo design system — v4 "Workbench"

Status: v4 (2026-10-31), a full visual redesign over v3 (2026-10-15; v1 2026-10-14). Source of truth for every screen. Tokens live in `src/renderer/styles.css` (`:root`, `[data-theme]`); chrome faces in `src/renderer/chromeFonts.ts`; icons in `src/renderer/ui/Icons.tsx`. If a screen needs a value that is not here, add it here first. The v3 baseline and the reasons it was replaced are in `docs/design/CRITIQUE-v4.md` (round 0).

## 1. Intent

**A workbench, not a dashboard.** Quvrelo is where students and pros *make* things, so the chrome is a set of tools laid out around the work: rounded **islands** (tool dock, left rail, stage, inspector) sitting on a darker **bed**, the way instruments sit on a bench. The work (the canvas) is the brightest, largest thing in the window; everything else is quieter and one step back.

v3 was correct but anonymous: a Linear/Raycast clone in teal and Inter, every region a flat slab cut by 1px lines, every label an uppercase micro-cap, every control a grey outlined box. It read as "an app template", not as a creative tool anyone would choose over Affinity or Photoshop. v4 keeps v3's discipline (one accent, tabular numbers, keyboard-first, AA/AAA contrast) and adds a point of view:

- **Warm ink, not cold graphite.** Neutrals carry a trace of warmth (paper and ink, not server-room grey), so the chrome feels like a studio and photographs sit naturally in it.
- **One signal colour: orange.** Signal orange (`#ff6a3d` dark, `#b3390a` light) is the colour of "do this" (the active tool, the one primary action, focus). It is warm, energetic for a classroom, and unlike the teal/violet of generic AI-era tooling. Canvas selection is a *different* colour (selection blue), so the chrome accent never fights the artwork.
- **An ink tile for "where am I".** Primary navigation (the studio switch) uses an inverted tile (light ink on dark, dark on light), a distinctive, high-contrast way to say "you are here" without spending the accent.
- **Editorial type at the front door.** The interface is set in Geist (engineered, compact, crisp at 12px); the Welcome screen speaks once in a large serif (Instrument Serif, italic accent word) so the first impression is of a creative tool with taste, not a settings page.
- **Students first-glance, pros at speed.** Sentence-case section titles instead of shouty micro-caps, real artwork on the start cards showing what each studio makes, and roomier hit targets (36px tools, 30px layer rows) without losing density.

Feel references (studied for structure and restraint, nothing copied): Figma UI3 and Affinity V3 (islands, floating dock), seesaw.website (editorial serif display, confident single accent, generous negative space), Mobbin patterns from Framer, Arc and Linear (inverted active tab, pill search, segmented panel tabs), inspo (github.com/Nutlope/inspo) for the "show the work, hide the chrome" principle. Notes: `docs/design/refs/NOTES.md`.

## 2. Anti-slop rules (reviewable, each is a checklist item)

1. No gradients on chrome, buttons, cards or logos (gradients only inside user artwork and the colour picker). No glass, no blur, no glows, no purple-to-blue anything.
2. No emoji, no unicode glyphs as icons. Every icon comes from `Icons.tsx`; illustrations are only the start-card line drawings (§8 Welcome), drawn with tokens.
3. **One chrome accent** (signal orange) in exactly these roles: the active tool, the one primary button per view, focus rings, "on" states (checkbox, slider fill, toggle icon, checklist progress), the selected preset ring, the italic word in the Welcome title and text links. Status is never orange.
4. **One canvas accent** (selection blue `#3d8bff`), only on the canvas overlay (selection, handles, hover outline, text caret). Margins are magenta, guides cyan, as in print tools.
5. **Ink tile** (`--c-ink-tile`) only for primary navigation: the studio switch.
6. Radii from tokens only: `--r-1` 6px (controls, rows), `--r-2` 10px (popovers, cards, tool buttons, nav rows), `--r-3` 14px (islands, dialogs, welcome cards), `--r-full` (studio switch, search pills, knobs, count pills). `tests/unit/shellLint.test.ts` rejects literal px radii.
7. Elevation is tone first: bed < stage < island < raised < popover. Islands carry only a 1px `--c-line` ring; only popovers, dialogs and toasts cast a shadow.
8. Left-aligned, grid-aligned. The only display type is the Welcome title.
9. Every number is tabular; keycaps and ruler labels are Geist Mono.
10. Motion ≤ 150 ms, ease-out, opacity/transform only, removed under `prefers-reduced-motion` and the in-app setting.
11. Nothing is decorated unless it carries meaning.

## 4. Type

- **UI: Geist** (Vercel, SIL OFL 1.1; `@fontsource-variable/geist`, variable 100–900, bundled offline). Chosen over Inter for its engineered, slightly condensed forms that stay crisp at 11–13px and give the app its own voice.
- **Mono: Geist Mono** (OFL; `@fontsource/geist-mono` 400/500) for keycaps, ruler labels and code.
- **Display: Instrument Serif** (OFL; `@fontsource/instrument-serif` 400 + italic) for the Welcome title only.
- Document typefaces (Inter, Merriweather, Roboto Slab, Caveat, Atkinson, OpenDyslexic, EB Garamond) are content, never chrome; they stay in `main.tsx` mirroring `core/pdfFonts.ts`. The dyslexia-friendly chrome option swaps `--font-ui`.

| Role | Size / line | Weight | Use |
|---|---|---|---|
| `micro` / section title | 12 / 16 | 600, sentence case, `text-2` | panel sections, dialog groups, menu and palette headings |
| `ui` | 12 / 16 | 400 / 500 | panel and toolbar text, inputs |
| `body` | 13 / 20 | 400 | dialog body, menus, nav rows |
| `title` | 14–15 / 20 | 600, −0.01em | dialog titles, welcome section heads, start-card titles |
| `display` | 52 / 56 | Instrument Serif 400, italic accent word | Welcome title only |

Weights: 400 body, 500 labels and active states, 600 titles. Never 700+ in chrome.

**Case.** Sentence case for every string Quvrelo draws, and v4 drops CSS uppercasing too: section labels read "Appearance", not "APPEARANCE". Exceptions as before: native menu items keep platform Title Case (`shared/menu.ts`) and so do the palette rows that mirror them; proper nouns keep their capitals. Enforced by `tests/unit/sentenceCase.test.ts`.

## 5. Space, size, grid

4px base; steps 2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48. **Shell v4:** a 6px **gutter** (`--gutter`) separates islands from each other and from the window edge. Top bar `48` (`--h-top`) and status bar `30` live on the bed. Columns: tool dock `52` (`--w-tools`, 38×36 buttons) · left rail `252` (`--w-rail`) · stage (context bar `40` on top, canvas below; one island) · inspector `292` (`--w-inspector`). Panel header `44` holding a full-width segmented tab track. Control heights: `24` panel inputs and segmented, `28` buttons, `30` top-bar search, `32` studio switch, `34` dialog actions, `36` welcome actions and search. Layer rows `30`, nav rows `30`, recent rows `44`.

**Units.** Every length the user reads or types is in the document's own unit (`settings.unit`), never a global preference. One formatter and one parser in `core/units.ts` feed the inspector, context bar, status bar, rulers, Document setup and Export. Stroke widths and brush sizes stay in px/pt.

## 6. Radius, elevation, motion

- Radius: `--r-1: 6px` · `--r-2: 10px` · `--r-3: 14px` · `--r-full: 999px`; derived `--r-tile: calc(var(--r-1) - 2px)` (tiles inset in a track, checkboxes) and `--r-hairline: 1px` (2px tracks and insertion bars). The stage island is split: context bar takes the top corners, canvas the bottom corners.
- Elevation: islands `0 0 0 1px --c-line`; `--e-1` popover = ring + 1px inner top highlight + `0 8px 24px` shade; `--e-2` dialog = ring + highlight + `0 24px 64px`. Buttons carry a 1px bottom shade (primary also a faint inner top highlight) so they read as pressable, not as outlined boxes.
- Motion: `--dur: 140ms`, `--ease: cubic-bezier(.2,.8,.2,1)`. Allowed: colour/opacity fades, 4px toast and flyout slides, dialog 4px rise. No bouncing, no scaling on hover.

## 7. Iconography

Custom set (`src/renderer/ui/Icons.tsx`): 20×20 grid, 16px live area, 1.5 stroke, round caps and joins, `currentColor`. Displayed at 20px in the tool dock and 16px inline (stroke 1.75). v4 sits them in larger, softer targets: tool buttons are 38×36 with `--r-2`, so the active tool reads as a solid orange key with accent-ink glyph. Studio glyphs (aperture, node curve, columns) appear in the studio switch, where the active one takes `--c-ink-tile-icon`. Start-card artwork (Welcome) is the one place line drawings appear: 1–2px strokes in the text ramp with a single accent element, drawn as inline SVG with tokens (`StartArt` in `Welcome.tsx`).

App icon / logo unchanged (graphite tile, off-white ring, one accent bar for the Q tail; `build/icon.svg`, `build/icon-small.svg`, rendered by `scripts/render-icons.cjs`).

Icon buttons: `tip(label, commandId | key)` from `ui/tooltip.ts` (aria-label, data-tip, data-keys, aria-keyshortcuts). Never the native `title` attribute.

## 8. Components

**Shell v4 layout.** Four islands on the bed under the top bar: tool dock · left rail (document structure) · stage (context bar on top of the canvas) · inspector, 6px apart, `--r-3` corners and a 1px `--c-line` ring each. Tab (outside a field) hides both rails. Grid and geometry live in `ui/shell.css`; nothing in the shell is positioned with inline styles except runtime geometry (popover/toolbar coordinates, virtualised rows, font-face previews), which `tests/unit/shellLint.test.ts` enforces.

**Top bar (48, on the bed, no hairline), three semantic zones** (Mobbin cross-app pattern 4). The outer columns are equal width and the centre column holds only the studio switch, so the switch sits on the window's centre line (±1px, e2e-checked).
1. *Identity* (left): app mark · document name (500, truncates at 280; click to rename in place, Enter commits, Esc cancels) · save state as quiet 11px text with a 6px dot: `Saved` (hollow `text-3` dot), `Edited` (solid `text-2` dot, `text-2` label; status is never accent, §2 rule 4), `Not saved` (never saved) · a 16px hairline · Undo · Redo · Place image (28×28 icon buttons).
2. *Studio* (centre): the studio switch, nothing else.
3. *Outbound* (right): **Search commands** field-button (a 30 × 232 pill on `--c-panel`, hairline; 16px search icon, "Search commands" 12 `text-3`, `Ctrl` `K` keycaps; opens the command palette; below 1280px it collapses to a 30 × 30 icon button), then Open · Save · Keyboard shortcuts · Preferences icon buttons, then **Export** as the only filled primary button in the bar (icon + label, 28 high). Align and boolean actions moved to the inspector and the selection toolbar.

**Studio switch.** A 32-high pill on `--c-panel` with a hairline, 3px inner padding, 24-high pill segments; the active segment is the **ink tile** (`--c-ink-tile` fill, `--c-ink-tile-text` label, `--c-ink-tile-icon` glyph; HC: yellow with black ink). Neither colour-coded nor underlined. Keyboard: arrow keys move, Enter selects.

**Tool dock (52 wide).** An island (`--c-panel`, `--r-3`). 38×36 buttons with `--r-2`, 2px gap, groups divided by a 20px `--c-line` hairline. Active = solid accent with accent-ink icon. Tooltips show name + shortcut as keycaps. **Flyouts:** related tools share one button (layout and groups in `state/toolGroups.ts`): it shows the active or last-used member and carries a 4px corner triangle (bottom-right, 3px inset, `currentColor` at 80 %). Click uses the shown tool; right-click, a 350ms long-press, →, Alt+↓, Shift+F10 or the context-menu key open the flyout (press-drag-release on an item picks it). Flyout = `role="menu"` beside the button (4px gap, first row level with the button): `--c-popover`, `--r-2`, `--e-1`, 4px padding, 28px `menuitemradio` rows with 4px radius (check · 16px icon · name · keycap in `text-3`), the shown tool checked with `--c-press` fill. High contrast uses the §9 selection vocabulary: checked = solid `#ffd400` tile with black text, icon and keycap, focused = the HC ring (3px yellow outline, 2px offset) on a black row, hover = 1px white inset; rows are 6px apart so a ring never touches a checked tile. ↑/↓/Home/End move, Enter/Space or a tool's letter picks, Esc/←/Tab close and return focus. Shift + any member's key cycles the group; a member without its own key advertises `Shift+<group key>` in its tooltip. Tool keys are per studio (`TOOL_KEYS` in `state/toolGroups.ts`). **Photo** has a Shapes flyout after Text (Rectangle · Ellipse · Polygon · Star, key `U`, Shift+U cycles, since M is the marquee and E the eraser there); a shape drawn in Photo is a vector layer inserted directly above the active layer. 120ms fade + 4px slide, none under reduced motion. Colour chips at the bottom: two overlapping 20px squares, 1px line-strong border, swap icon.

**Context bar (40).** The top of the stage island (`--c-panel`, top corners `--r-3`, hairline below). Tool name at 600, then controls in groups separated by a 16px hairline. Sliders show label, 96px track, tabular value. Modes (New/Add/Subtract/Intersect) are a segmented control. Hint text is `text-3`, never competes with controls. **Priority+ overflow** (`controls/CtxOverflow.tsx`): the bar never scrolls and never cuts a word. When its groups don't fit the canvas column, the hint is dropped first (a hint is dropped rather than shown cut short), then groups collapse, lowest `<Pri n>` first (ties right to left), into a trailing ghost **More ▾** button whose popover holds them in a column. Page navigation and crop Cancel/Apply never collapse. Layout Move: Pages (always) · Margins (4; T · B · L · R, the same order as Document setup) · Document setup (3) · Facing pages (2.5) · Columns (2) · Bleed (1). E2e-checked for every studio and tool at 1280 and 1440 (`scrollWidth ≤ clientWidth`).

**Left rail (252).** An island. Tabs **Layers · Pages · Assets** (Figma/Framer pattern) in a 44px header: one full-width segmented track (`--c-seg-track`, hairline, `--r-2`), each tab `flex: 1`, the active one a raised `--c-seg-on` tile with a soft shade (never overflowing: five Photo inspector tabs fit in 292px; arrow keys/Home/End move and select). Default tab: Layers in Photo and Vector, Pages in Layout; the choice is remembered per studio. Assets holds document swatches + recent colours, then Shapes & symbols, then placed Images (with a teaching empty state).

**Inspector (292).** An island with the same tab track. Tabs **Design · Adjust (Photo only) · History**, remembered per studio. The Design tab is grouped by concern, in this order:
1. Header 32: object name (13/600, the same display name as the layer row) and, when it differs from the name, its kind in `text-3` 11/500.
2. Align bar 36: six align buttons, hairline, distribute H/V (enabled at 3+), Boolean menu (Vector, 2+).
3. **Appearance**: Fill row · Stroke row (+ width · dash · cap · join when on) · Opacity slider · Blend. Text and text frames show *Colour* in place of Fill. This is the one home for Opacity and Blend in every studio, Photo included (pixel layers show Opacity · Blend here).
4. **Text** (text and text frames only; CRITIQUE-4 N11): the full, persistent home for type. Font picker (full width, set in its own face) · Style (weight + italic, "Bold italic") + Size in pt (grid2) · Leading (×, line-height multiple) + Tracking (thousandths of an em), each with a 16px glyph scrub label and a tooltip (grid2) · alignment as an icon segmented control (left · centre · right · justify) · a ghost **More type options** disclosure with Capitals (Normal · Small caps · All small caps) and the Kerning and Underline checkboxes (the OpenType basics the canvas, SVG and PDF writers honour; the PDF shapes text with the embedded font's GSUB/GPOS, so kerning is TJ spacing and small caps are the font's smcp/c2sc glyphs, or Chromium-style 70 % capitals when the face has none, always as real text). Layout text frames add, below alignment: paragraph / character style pickers, space before/after and indents, Align to baseline grid, **Hyphenate** with its language (English UK/US), the keep options (Keep with next · Keep lines together · Widow and orphan control) and **Tab stops** (position in the document unit, a left/centre/right/decimal icon segmented control, leader, remove; a + in the sub-label adds one). Editing a table cell shows the same section with only the character style picker; alignment and leading go to the cell's own format.
5. **Transform** (the document unit in the header): one 4-up row X · Y · W · H (no unit suffix, so five digits fit), then R · S · flip H · flip V.
6. The object's own section last, titled for what it edits so it never repeats the header: *Corners* (rectangle radius), *Sides* (polygon), *Points* (star points/inner), *Text frame* (columns · gap · inset, frame fill, then *Link frames* and *Unlink* as two `btn sm ghost` buttons; Unlink is disabled while the frame has no link), *Image fit* (picture frame fit/zoom/offset/replace), *Pixels*; then Mask.
Nothing selected: Document (title, size in the document unit with the output pixels as an 11px `text-3` second line, "2480 × 3508 px at 300 dpi", pages, background chip) and *New objects* (default fill/stroke rows). Rows use a 56px label column; sections are flat with a micro-label disclosure (remembered per section), hairline between, and a section you expand scrolls itself into view.

**Colour control (one everywhere).** `ColorChipButton` is the only colour trigger in the shell: a 20px chip (optionally with a chevron in the context bar) that opens `ColorPopoverBody` in a popover. There is one popover body: title, then the paint-type tabs **None · Solid · Linear · Radial** as the first row (always all four, in that order), then the picker (Solid) or the gradient editor. A target that can't take a type (brush and flood fill: no None, no gradients; text: no None; document background: no gradients) shows that tab disabled with a tooltip, never hidden, so the body is identical in the inspector, context bar, selection toolbar, tool rail and Document section. No "None" checkbox anywhere. The chip takes a `Paint` and returns a `Paint`; defaults for new objects are read and written through `state/uiPaint.ts`, so a default fill or stroke can be a gradient too. The inspector's `PaintRow` is chip · hex field · add/remove; its chip opens to the *left* of the inspector so it never covers the panel. **Placement rule (every colour popover):** it never covers the inspector or the selected object it edits, so the change is visible live. An inspector chip places against the inspector's left edge (`right = inspectorLeft − 8`); a context-bar, selection-toolbar or tool-rail chip takes the first side that keeps the selection's screen bounds, the inspector and its own anchor clear (below/above the anchor, then left/right of the selection), and falls back to below only when nothing fits (`ui/controls/placement.ts`, unit- and e2e-tested). No native `<input type="color">` anywhere in the shell. Chrome is off limits too: a colour popover never rides over the top bar or the context bar (both are keep-clear rects; it opens below the context bar or beside the selection and slides horizontally; CRITIQUE-4 P2-19). A transparent document background shows the transparency checker in its chip (inspector and Document setup), never the None diagonal or a stale white swatch.

**Layers.** No header controls: opacity and blend are edited only in Design › Appearance (all studios). Row 28, full bleed: 16px indent per group level, chevron twisty, 24×20 thumbnail (4px radius, 1px `--c-line-strong` inner frame; vector thumbnails tint the type glyph with the fill, falling back to `text-3` when the fill is under 1.5:1 against the tile, so a white "Paper" layer never vanishes on the light theme), name (12; text layers that were never renamed show their text, whitespace collapsed, and only the CSS ellipsis truncates it (never a word cut plus an ellipsis), with the full name in the row tooltip; "Text Frame" only when empty; F2 renames and the name then sticks), status icons (mask, live adjustments) in `text-3`, then lock/eye toggles that appear on hover, keyboard focus or selection, and stay visible while they carry state (hidden, locked); at rest a stateless toggle takes no width, so the name uses the whole row before the ellipsis. Rows are 30 high, inset 6px with `--r-2`. Hover = `--c-hover` fill only; selected = accent-wash fill + name at 500 (no bar, no ring, so selected never looks like focus) (hover on a selected row keeps the wash, never the grey hover). Hovering a row draws the hover outline on the canvas. High contrast follows the §9 selection vocabulary: selected = solid yellow fill with black name, icons and toggles; keyboard focus = 3px yellow ring 2px outside a black row; selected + focused = both; hover = 1px white inset; rows sit 6px apart; no washes. **Empty state:** a teaching block, never a bare line: 32px glyph tile, “No layers yet” (13/600), one line on what lives here, then ghost actions *Place image* · *Draw a shape* (Photo: *Paint*) · *Add text*, and “Or drop an image file onto the canvas.” in `text-3`. When the canvas shows its own empty card (an empty page), the card owns the actions and the Layers empty state shrinks to glyph, title and one line, so two empty states never offer the same buttons. Drag: the dragged row dims, insertion = 2px accent line with a 6px ring at its start, above or below the hovered row. Keyboard: ↑/↓ move focus, ←/→ collapse/expand, Enter selects, F2 renames, Alt+↑/↓ reorders, Alt+H toggles visibility. Footer actions are 24×24 icon buttons: **+** (Add layer) opens a menu above it: Pixel layer · Group selection (2+) · Place image… · in Photo an *Adjustment* heading with the adjustment list (disabled, "Select a pixel layer first", until a pixel layer is selected); then Group · Mask · Duplicate · Forward · Backward · Delete.

Used for every one-of-few choice: paint type, colour model, selection mode, frame fit, dialog options (orientation, background, update channel, resize mode, export pages/background). There is no other segmented style (`.seg` and `.choice-row` are gone, the Curves channel switch included; `tests/unit/shellLint.test.ts` guards it). Tokens: track `--c-seg-track` with a `--c-line` hairline; active tile `--c-seg-on` + 1px `--c-seg-ring`, label `--c-seg-on-text` at 500.

|---|---|---|---|
| track | `#1e1f21` | black 6 % | `#000` + 1px white |
| active tile | `#222326` + 1px white 34 % ring | `#fff` + 1px black 43 % ring | `#ffd400` fill, black label |

Disabled never means translucent accent. The contrast audit checks that the active tile differs from the track (fill ≥ 1.4:1 or ring ≥ 3:1) on panels and in dialogs, in all three themes.

**Text controls: one quick home.** Type has exactly two homes: the full set in Inspector › Text, and one quick set outside it, which is the **context bar** (font · size · B · I · U · alignment; leading, tracking and OpenType live only in the inspector). The floating selection toolbar carries no text controls. The context bar is the quick home, not the floating toolbar, because: it is visible while text is being typed (the toolbar hides during text editing, which is exactly when a student reaches for size or bold); it sets the defaults for the Text and Text frame tools before any text exists; it cannot be switched off (Preferences › Canvas turns the floating toolbar off); it never covers the text being edited; and it sits in the same place every time, where students already look for tool options (Affinity, Photoshop). E2e-checked: a selected text frame shows exactly one font trigger outside the inspector.

## 9. Accessibility (must not regress)

Focus ring 2px `--c-focus` + 1px offset on every interactive element; high-contrast uses 3px.

**High-contrast selection vocabulary (one rule for every list).** Written once at the end of `styles.css`; no other CSS may style a selected row in high contrast (`tests/unit/shellLint.test.ts`), and `tests/e2e/hc-selection.spec.ts` checks the computed styles.
- *Selected / current / checked / on* (Layers rows, History current step, Preferences / Shortcuts / Export / New-document nav, preset and template tiles, theme tiles, Pages thumbnails, the tool flyout, menus, the command-palette and font-list cursor rows, `.btn.selected`, small icon toggles such as Bold/Italic, Snap; segmented controls, panel tabs and the studio switch already use it): solid `#ffd400` fill, black text, icons, counts and keycap frames, no outline, no wash. Colour swatches, whose fill is their content, draw selected as a 2px yellow edge *inside* the swatch.
- *Keyboard focus*: 3px `#ffd400` outline, 2px offset, on a black row.
- *Selected + focused*: the fill plus the ring; the 2px offset is the black gap between them.
- *Hover*: 1px white inset on a black row; a selected row keeps its fill.
- Rows that take focus sit 6px apart and 6px inside their scroller (Layers, dialog side lists, menus, History, the flyout), so a ring is never clipped and never touches a neighbouring fill.

**High-contrast disabled and dimmed states.** Never translucent (opacity turns yellow into olive and white into a grey that reads as another colour): ink is `--c-disabled` (`#8f8f8f`, still 6.6:1 on black); a bordered control's border turns 1px dashed white; a disabled accent control (primary button, checked box, slider fill, the active segment) is black with a dashed white edge, never yellow. Dimmed but enabled states (a search group with no match, redo-able History steps, a hidden adjustment, paint or layer) use the same ink. Keycaps are one 1px white frame on black; every HC hairline, scroll edges included, is 1px white. All icon buttons have `aria-label`; tooltip text equals label. Target size ≥ 24×24 (WCAG 2.2 AA 2.5.8). Contrast table above. No information by colour alone (active tool also has fill + `aria-pressed`). Reduced motion honoured. Forced-colours supported via high-contrast theme.
